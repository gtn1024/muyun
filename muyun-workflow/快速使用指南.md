# MuYun Workflow 快速使用指南

## 三步快速上手

### 第一步：创建流程定义

在系统中创建一个完整的流程定义（包括节点和流转）：

```java
// 1. 创建流程定义
String definitionId = workflowDefinitionController.create(Map.of(
    "v_name", "请假审批",
    "v_code", "leave_approval",
    "v_category", "人事",
    "dict_workflow_status", "draft"
));

// 2. 创建开始节点
String startNode = workflowNodeController.create(Map.of(
    "id_at_workflow_definition", definitionId,
    "v_name", "开始",
    "v_code", "start",
    "dict_node_type", "start",
    "i_order", 1
));

// 3. 创建审批节点
String approveNode = workflowNodeController.create(Map.of(
    "id_at_workflow_definition", definitionId,
    "v_name", "经理审批",
    "v_code", "manager_approve",
    "dict_node_type", "approve",
    "dict_assignee_type", "user",
    "ids_assignee", List.of("user_id_001"),  // 指定审批人
    "i_order", 2
));

// 4. 创建结束节点
String endNode = workflowNodeController.create(Map.of(
    "id_at_workflow_definition", definitionId,
    "v_name", "结束",
    "v_code", "end",
    "dict_node_type", "end",
    "i_order", 3
));

// 5. 创建流转：开始 -> 审批
workflowTransitionController.create(Map.of(
    "id_at_workflow_definition", definitionId,
    "id_from_node", startNode,
    "id_to_node", approveNode,
    "v_name", "提交"
));

// 6. 创建流转：审批 -> 结束
workflowTransitionController.create(Map.of(
    "id_at_workflow_definition", definitionId,
    "id_from_node", approveNode,
    "id_to_node", endNode,
    "v_name", "同意"
));

// 7. 激活流程
workflowDefinitionController.update(definitionId, Map.of(
    "dict_workflow_status", "active"
));
```

### 第二步：业务模块实现 IWorkflowAbility

让你的业务 Controller 实现 `IWorkflowAbility` 接口：

```java
@Startup
@Path(BASE_PATH + "/leave_request")
public class LeaveRequestController extends ScaffoldForPlatform
    implements IWorkflowAbility {

    @Inject
    WorkflowEngine workflowEngine;

    @Override
    public String getMainTable() {
        return "leave_request";
    }

    @Override
    public void fitOut(TableWrapper wrapper) {
        wrapper
            .setComment("请假申请")
            .setPrimaryKey(PresetColumn.ID_POSTGRES_UUID)
            .setInherit(BaseBusinessTable.TABLE)
            .addColumn("v_title", "标题")
            .addColumn("i_days", "请假天数")
            .addColumn("v_reason", "原因")
            .addColumn("dict_status", "状态", "'draft'")
            .addColumn("id_at_workflow_instance", "流程实例ID");
    }

    // 关键：指定使用哪个工作流
    @Override
    public String getWorkflowCode() {
        return "leave_approval";  // 对应第一步创建的流程编码
    }

    // 提交审批接口
    @POST
    @Path("/submit/{id}")
    public String submit(@PathParam("id") String id) {
        // 启动工作流
        String instanceId = workflowEngine.startProcess(
            getWorkflowCode(),
            id,
            "leave_request",
            getUser().getId(),
            getWorkflowVariables(id)
        );

        // 更新业务状态
        this.update(id, Map.of(
            "dict_status", "approving",
            "id_at_workflow_instance", instanceId
        ));

        return instanceId;
    }

    // 提供流程变量（可选）
    @Override
    public Map<String, Object> getWorkflowVariables(String id) {
        Map<String, ?> data = view(id);
        return Map.of(
            "days", data.get("i_days"),
            "starterId", getUser().getId()
        );
    }

    // 审批通过后的回调
    @Override
    public void afterWorkflowApproved(String id) {
        this.update(id, Map.of("dict_status", "approved"));
    }

    // 审批驳回后的回调
    @Override
    public void afterWorkflowRejected(String id) {
        this.update(id, Map.of("dict_status", "rejected"));
    }
}
```

## 常用 API 接口

### 业务侧接口

```java
// 1. 启动流程
String instanceId = workflowEngine.startProcess(
    workflowCode,      // 流程编码
    businessKey,       // 业务单据ID
    moduleAlias,       // 模块别名
    starterId,         // 发起人ID
    variables          // 流程变量
);

// 2. 完成任务
workflowEngine.completeTask(taskId, action, comment, formData);

// 3. 转办任务
workflowEngine.transferTask(taskId, toUserId);

// 4. 取消流程
workflowEngine.terminateProcess(instanceId, reason);
```

### HTTP REST 接口

```bash
# 获取我的待办
GET /api/platform/workflow_task/todo?page=1&size=10

# 获取我的已办
GET /api/platform/workflow_task/done?page=1&size=10

# 完成任务
POST /api/platform/workflow_task/complete/{taskId}
{
  "v_action": "同意",
  "v_comment": "同意此申请"
}

# 查看流程历史
GET /api/platform/workflow_instance/history/{instanceId}
```

## 节点类型说明

| 节点类型 | 说明 | 是否需要办理人 |
|---------|------|---------------|
| start | 开始节点，每个流程只能有一个 | 否 |
| end | 结束节点，可以有多个 | 否 |
| approve | 审批节点，需要人工审批 | 是 |
| countersign | 会签节点（待实现） | 是 |
| condition | 条件节点（待实现） | 否 |
| parallel | 并行节点（待实现） | 否 |

## 办理人类型说明

| 类型 | 说明 | 示例 |
|-----|------|------|
| user | 指定具体用户 | `"ids_assignee": ["user001", "user002"]` |
| role | 指定角色（该角色下的所有用户） | `"ids_assignee": ["manager_role"]` |
| department | 指定部门（该部门下的所有用户） | `"ids_assignee": ["dept001"]` |
| starter | 发起人 | 无需指定 ids_assignee |
| superior | 发起人的上级 | 无需指定 ids_assignee |
| dynamic | 动态计算（根据流程变量） | 待实现 |

## 流程状态说明

### 流程定义状态
- `draft`: 草稿，可以编辑
- `active`: 已激活，可以启动实例
- `suspended`: 已暂停，不能启动新实例
- `archived`: 已归档，只读

### 流程实例状态
- `running`: 运行中
- `completed`: 已完成
- `terminated`: 已终止
- `suspended`: 已暂停

### 任务状态
- `pending`: 待办
- `completed`: 已完成
- `rejected`: 已驳回
- `transferred`: 已转办
- `cancelled`: 已取消

## 典型场景示例

### 场景1：简单审批（一级审批）

流程：**开始 → 审批 → 结束**

```
用户提交 → 经理审批 → 结束
```

### 场景2：多级审批

流程：**开始 → 审批1 → 审批2 → 审批3 → 结束**

```
用户提交 → 经理审批 → 总监审批 → CEO审批 → 结束
```

### 场景3：条件审批

根据金额决定审批路径：

```
用户提交 → [金额判断]
           ├─ ≤1000元 → 经理审批 → 结束
           ├─ ≤5000元 → 总监审批 → 结束
           └─ >5000元 → CEO审批 → 结束
```

实现方式：
```java
// 创建流转时指定条件
workflowTransitionController.create(Map.of(
    "id_from_node", startNode,
    "id_to_node", managerNode,
    "v_name", "提交",
    "v_condition", "amount <= 1000"  // 条件表达式
));
```

### 场景4：驳回重审

支持驳回到上一节点或开始节点：

```
开始 → 审批1 → 审批2 → 结束
  ↑       ↓       ↓
  └───────┴───────┘（驳回）
```

实现方式：
```java
// 创建驳回流转
workflowTransitionController.create(Map.of(
    "id_from_node", approveNode,
    "id_to_node", startNode,
    "v_name", "驳回"
));
```

## IWorkflowAbility 接口方法

| 方法 | 必须实现 | 说明 |
|------|---------|------|
| `getWorkflowCode()` | ✅ 是 | 返回工作流编码 |
| `beforeSubmitWorkflow()` | ❌ 否 | 提交前校验 |
| `getWorkflowVariables()` | ❌ 否 | 提供流程变量 |
| `afterWorkflowStarted()` | ❌ 否 | 流程启动后回调 |
| `afterWorkflowApproved()` | ❌ 否 | 审批通过后回调 |
| `afterWorkflowRejected()` | ❌ 否 | 审批驳回后回调 |
| `afterWorkflowCompleted()` | ❌ 否 | 流程完成后回调 |

## 注意事项

1. ⚠️ **流程必须先激活才能使用**
   ```java
   workflowDefinitionController.update(definitionId, Map.of(
       "dict_workflow_status", "active"
   ));
   ```

2. ⚠️ **每个流程只能有一个开始节点**

3. ⚠️ **审批节点必须指定办理人**
   ```java
   "dict_assignee_type", "user",
   "ids_assignee", List.of("user001")
   ```

4. ⚠️ **流程编码必须唯一**
   ```java
   "v_code", "leave_approval"  // 不能重复
   ```

5. ⚠️ **业务表需要关联流程实例**
   ```java
   .addColumn("id_at_workflow_instance", "流程实例ID")
   ```
